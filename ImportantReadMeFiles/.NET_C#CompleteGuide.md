## 1. What is .NET? (The Big Picture)

### For Freshers

**.NET** is a free, open-source **development platform** by Microsoft. You use it to build:

- Console apps
- Web APIs (like Spring Boot in Java)
- Web apps (Blazor, ASP.NET)
- Desktop apps (WPF, WinForms)
- Mobile apps (MAUI)
- Cloud functions (Azure)

**C#** is the primary language used with .NET — similar to how **Java** is used with the JVM.

### For Java Developers

| Concept | Java World | .NET World |
|---|---|---|
| Platform | JVM (Java Virtual Machine) | CLR (Common Language Runtime) |
| Language | Java | C# (also F#, VB.NET) |
| Bytecode | `.class` files | IL (Intermediate Language) in `.dll` |
| Runtime | JRE | .NET Runtime |
| Build output | `.jar` / `.war` | `.dll` / `.exe` |
| SDK | JDK | .NET SDK |

> **TL;DR:** CLR = JVM, C# = Java, .dll = .jar, .NET SDK = JDK

## 2. Key File Types Explained

Understanding these file types is essential before diving into builds and packages.

### 📦 `.dll` — Dynamic Link Library

- The **compiled output** of your C# project
- Equivalent to a **`.jar` file** in Java
- Contains your code in **IL (Intermediate Language)** — not machine code
- When your app runs, the CLR (Common Language Runtime) converts IL → machine code (JIT compilation)
- NuGet packages you install also come as `.dll` files

```
YourProject.dll  →  like  →  myapp.jar
```

**Why "Dynamic"?** Because multiple applications can share and load the same `.dll` at runtime — they don't need to embed a copy.

---

### ⚙️ `.exe` — Executable File (Windows only)

- The **entry-point launcher** for your application
- On Windows, double-clicking `.exe` starts your app
- On Linux/Mac, there is no `.exe` — you run the `.dll` directly via `dotnet YourApp.dll`
- Contains a small bootstrap that loads the CLR and calls your `.dll`

```
YourProject.exe  →  like  →  running  →  java -jar app.jar
```

---

### 📄 `.csproj` — C# Project File

- The **project configuration file** — defines what your project is, its dependencies, and build settings
- Written in XML
- Equivalent to **`pom.xml`** (Maven) or **`build.gradle`** (Gradle)

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>          <!-- Console app -->
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

  <ItemGroup>
    <!-- Your NuGet packages go here -->
    <PackageReference Include="Newtonsoft.Json" Version="13.0.3" />
  </ItemGroup>

</Project>
```

| `.csproj` field | Purpose | Maven equivalent |
|---|---|---|
| `TargetFramework` | Which .NET version to use | `<java.version>` in properties |
| `OutputType` | Exe = app, Library = dll | `<packaging>jar</packaging>` |
| `PackageReference` | External dependency | `<dependency>` block |

---

### 🔒 `.sln` — Solution File

- A **solution** is a container for one or more `.csproj` projects
- Equivalent to a **multi-module Maven project** (`parent pom.xml`)
- Used mainly in Visual Studio to group related projects (e.g., API project + Tests project + Shared library)

```
MySolution.sln
├── MyApi/MyApi.csproj
├── MyApi.Tests/MyApi.Tests.csproj
└── MySharedLib/MySharedLib.csproj
```

---

### 📋 `packages.lock.json` *(optional but recommended)*

- Locks exact package versions — like **`package-lock.json`** in npm or **`Pipfile.lock`** in Python
- Ensures every developer on the team gets the exact same dependency versions
- Enable it by adding `<RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>` to your `.csproj`

## 3. Package Manager — NuGet

### What is NuGet?

**NuGet** is the official package manager for .NET — similar to how:

| Platform | Package Manager | Registry |
|---|---|---|
| Java | Maven / Gradle | [Maven Central](https://mvnrepository.com/) |
| Node.js | npm / yarn | [npm Registry](https://registry.npmjs.org/) |
| Python | pip | [PyPI](https://pypi.org/) |
| **.NET** | **NuGet** | [NuGet Gallery](https://www.nuget.org/packages) |

### How it works

1. You search for a package on [nuget.org](https://www.nuget.org/packages)
2. You install it via CLI / Visual Studio / manually in `.csproj`
3. NuGet downloads it to a **global cache** on your machine
4. Your project references it from the cache (not copied into the project folder)

> This is exactly how Maven downloads JARs to `~/.m2/repository/` — NuGet downloads packages to `~/.nuget/packages/`

## 4. Ways to Add External Dependencies

### Method 1 — .NET CLI *(Recommended)*

Best for developers comfortable with the terminal.

```bash
# Step 1: Navigate to your project folder
cd D:\DotNetPractice

# Step 2: Add a package
dotnet add package Newtonsoft.Json

# Step 3: Restore (download) all packages
dotnet restore

# Step 4: Verify installed packages
dotnet list package
```

✅ This **automatically updates** your `.csproj` file.

**Add a specific version:**
```bash
dotnet add package Newtonsoft.Json --version 13.0.3
```

**Remove a package:**
```bash
dotnet remove package Newtonsoft.Json
```

---

### Method 2 — Manually Edit `.csproj`

Best when you know the exact package name and version.

```xml
<ItemGroup>
  <PackageReference Include="Newtonsoft.Json" Version="13.0.3" />
  <PackageReference Include="Humanizer" Version="2.14.1" />
  <PackageReference Include="Polly" Version="8.3.0" />
</ItemGroup>
```

Then restore:
```bash
dotnet restore
```

✅ Same as manually editing `pom.xml` in Maven — then running `mvn install`.

---

### Method 3 — Visual Studio GUI *(Easiest for Beginners)*

1. Open your project in **Visual Studio**
2. Right-click on project in Solution Explorer → **Manage NuGet Packages**
3. Click the **Browse** tab → search for your package (e.g., `Newtonsoft.Json`)
4. Click **Install**
5. Visual Studio automatically updates `.csproj` and restores packages

✅ Best for beginners — no command line needed.

---

### Method 4 — VS Code with C# Dev Kit

1. Open Command Palette → `Ctrl+Shift+P`
2. Type: `.NET: Add NuGet Package`
3. Search and select the package
4. Extension updates `.csproj` automatically

## 5. Commonly Used NuGet Packages

### 🔵 JSON Handling

#### Newtonsoft.Json (Json.NET)
The most popular JSON library in .NET history.

```bash
dotnet add package Newtonsoft.Json
```

```csharp
using Newtonsoft.Json;

var person = new { Name = "Alice", Age = 30 };
string json = JsonConvert.SerializeObject(person);
// Output: {"Name":"Alice","Age":30}

var deserialized = JsonConvert.DeserializeObject<Person>(json);
```

> **Note:** .NET also has a **built-in** `System.Text.Json` (no install needed) — faster but less feature-rich than Newtonsoft.

---

### 🔵 HTTP Clients & Resilience

#### Polly — Retry & Resilience
Handles retries, circuit breakers, timeouts for HTTP calls.

```bash
dotnet add package Polly
```

```csharp
var retryPolicy = Policy
    .Handle<HttpRequestException>()
    .WaitAndRetry(3, attempt => TimeSpan.FromSeconds(attempt));

retryPolicy.Execute(() => CallExternalApi());
```

> Java equivalent: **Resilience4j**

---

### 🔵 Logging

#### Serilog — Structured Logging
Popular structured logging library.

```bash
dotnet add package Serilog
dotnet add package Serilog.Sinks.Console
```

```csharp
Log.Logger = new LoggerConfiguration()
    .WriteTo.Console()
    .CreateLogger();

Log.Information("User {Name} logged in at {Time}", "Alice", DateTime.Now);
```

> Java equivalent: **Logback / SLF4J**

---

### 🔵 ORM (Database)

#### Dapper — Lightweight ORM
Simple micro-ORM for SQL queries.

```bash
dotnet add package Dapper
```

> Java equivalent: **MyBatis / JDBC Template**

#### Entity Framework Core — Full ORM
The full-featured ORM for .NET.

```bash
dotnet add package Microsoft.EntityFrameworkCore
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
```

> Java equivalent: **Hibernate / JPA**

---

### 🔵 Utility

#### Humanizer — Human-Readable Strings
Converts dates, numbers, enums into readable text.

```bash
dotnet add package Humanizer
```

```csharp
3501.ToWords();           // "three thousand five hundred and one"
DateTime.UtcNow.Humanize(); // "just now"
TimeSpan.FromDays(2).Humanize(); // "2 days"
```

#### AutoMapper — Object Mapping
Maps one object type to another (e.g., Entity → DTO).

```bash
dotnet add package AutoMapper
```

> Java equivalent: **MapStruct / ModelMapper**

---

### 🔵 Testing

#### xUnit — Unit Testing

```bash
dotnet add package xunit
dotnet add package xunit.runner.visualstudio
```

> Java equivalent: **JUnit**

#### Moq — Mocking

```bash
dotnet add package Moq
```

> Java equivalent: **Mockito**

## 6. How .NET Handles Dependencies Internally

```
You run:  dotnet add package Newtonsoft.Json
                    |
                    ▼
         NuGet fetches from nuget.org
                    |
                    ▼
    Downloaded to global cache:
    C:\Users\<User>\.nuget\packages\newtonsoft.json\13.0.3\
                    |
                    ▼
    Reference added to your .csproj
                    |
                    ▼
    obj/ folder updated (dependency map, lock files)
                    |
                    ▼
    On dotnet build → .dll copied to bin/ folder
```

### Global Package Cache

All packages downloaded once, shared across all your projects:

```
~/.nuget/packages/                     ← Linux/Mac
C:\Users\<User>\.nuget\packages\       ← Windows
```

> Exactly like Maven's `~/.m2/repository/` — no duplicate downloads per project.

## 7. Project Folder Structure Explained

```
MyProject/
├── MyProject.csproj       ← Project config (like pom.xml)
├── Program.cs             ← Entry point (like Main class)
├── appsettings.json       ← App configuration (like application.properties)
│
├── obj/                   ← 🔧 Temporary build files (auto-generated)
│   ├── MyProject.csproj.nuget.g.props
│   ├── project.assets.json    ← Dependency resolution map
│   └── Debug/net8.0/
│
└── bin/                   ← 📦 Final compiled output
    └── Debug/
        └── net8.0/
            ├── MyProject.dll      ← Your compiled app (like app.jar)
            ├── MyProject.exe      ← Windows launcher
            └── MyProject.pdb      ← Debug symbols (like .map files)
```

### `obj/` folder — What's inside?

| File | Purpose |
|---|---|
| `project.assets.json` | Full dependency tree (direct + transitive packages) |
| `*.nuget.g.props` | NuGet-generated MSBuild properties |
| `*.nuget.g.targets` | NuGet-generated MSBuild targets |
| Intermediate `.cs` files | Auto-generated code (e.g., from Source Generators) |

> ✅ Safe to delete. Recreated automatically on next `dotnet build` or `dotnet restore`.
> Add `obj/` and `bin/` to `.gitignore` — never commit them.

### `bin/` folder — What's inside?

| File | Purpose |
|---|---|
| `YourProject.dll` | Your compiled app in IL (Intermediate Language) |
| `YourProject.exe` | Windows launcher (not present on Linux/Mac) |
| `YourProject.pdb` | Debug symbols — maps IL back to your source code for debugging |
| `YourProject.runtimeconfig.json` | Tells the CLR which .NET version to use |
| `Newtonsoft.Json.dll` | Copies of all NuGet package DLLs your app needs |

## 8. How to Build & Run a .NET Project

### 8.1 `dotnet run` — Direct Run *(Most Common)*

```bash
dotnet run
```

- Compiles your code
- Restores packages if needed
- Runs the output — all in one step

> Java equivalent: `mvn exec:java` or running from IDE

---

### 8.2 `dotnet build` — Build Only

```bash
dotnet build
```

- Compiles code → outputs `.dll` and `.exe` to `bin/Debug/net8.0/`
- Does **not** run the app

```bash
# Then manually run:
dotnet bin/Debug/net8.0/MyProject.dll
```

> Java equivalent: `mvn compile` → `java -jar target/app.jar`

---

### 8.3 `dotnet publish` — Production Build

```bash
dotnet publish -c Release
```

Produces optimized output in:
```
bin/Release/net8.0/publish/
```

Run the published app:
```bash
dotnet YourProject.dll
```

> Java equivalent: `mvn package` → produces `target/app.jar` → `java -jar app.jar`

**Self-contained publish** (no .NET runtime needed on target machine):
```bash
dotnet publish -c Release -r win-x64 --self-contained true
```

This bundles the .NET runtime with your app — like a **fat JAR** / **uber JAR** in Java.

---

### 8.4 `dotnet test` — Run Tests

```bash
dotnet test
```

> Java equivalent: `mvn test`

## 9. Java (Maven) vs .NET (NuGet) — Full Comparison

| Feature | Java (Maven) | .NET (NuGet) |
|---|---|---|
| Project config file | `pom.xml` | `.csproj` |
| Package registry | Maven Central | NuGet Gallery |
| Dependency declaration | `<dependency>` | `<PackageReference>` |
| Install command | `mvn install` | `dotnet add package` |
| Build tool | Maven / Gradle | dotnet CLI / MSBuild |
| Build command | `mvn compile` | `dotnet build` |
| Run command | `mvn exec:java` | `dotnet run` |
| Test command | `mvn test` | `dotnet test` |
| Package command | `mvn package` | `dotnet publish` |
| Output artifact | `.jar` / `.war` | `.dll` / `.exe` |
| Bytecode | Java bytecode (`.class`) | IL in `.dll` |
| Runtime | JVM | CLR |
| Local package cache | `~/.m2/repository/` | `~/.nuget/packages/` |
| Version lock file | None built-in (use lockfile plugin) | `packages.lock.json` |
| Multi-project container | Parent `pom.xml` | `.sln` solution file |
| Entry point | `public static void main` | `static void Main` / top-level statements |

## 10. Common CLI Commands Cheat Sheet

```bash
# ── Project Setup ──────────────────────────────────────────
dotnet new console -n MyApp          # Create new console app
dotnet new webapi -n MyApi           # Create new Web API
dotnet new classlib -n MyLib         # Create new class library (DLL)
dotnet new sln -n MySolution         # Create solution file
dotnet sln add MyApp/MyApp.csproj    # Add project to solution

# ── Packages ───────────────────────────────────────────────
dotnet add package <PackageName>             # Install latest version
dotnet add package <PackageName> --version 1.2.3  # Install specific version
dotnet remove package <PackageName>          # Remove package
dotnet list package                          # List installed packages
dotnet list package --outdated               # Check for updates
dotnet restore                               # Download/restore all packages

# ── Build & Run ────────────────────────────────────────────
dotnet build                         # Compile the project
dotnet run                           # Build + run
dotnet run --project MyApp           # Run specific project in solution
dotnet publish -c Release            # Production build
dotnet clean                         # Delete bin/ and obj/

# ── Testing ────────────────────────────────────────────────
dotnet test                          # Run all tests
dotnet test --filter "TestMethod"    # Run specific test

# ── Info ───────────────────────────────────────────────────
dotnet --version                     # Check .NET SDK version
dotnet --list-sdks                   # List all installed SDKs
dotnet --list-runtimes               # List all installed runtimes
dotnet new list                      # List all available project templates
```

## 11. Beginner Pitfalls & Tips

### ❌ Don't commit `bin/` and `obj/` folders

Always add these to `.gitignore`:

```gitignore
bin/
obj/
*.user
.vs/
```

---

### ❌ Confusing `dotnet restore` vs `dotnet build`

- `dotnet restore` — **only downloads packages**, doesn't compile
- `dotnet build` — **compiles**, and also restores automatically
- You rarely need to run `dotnet restore` separately — `dotnet build` and `dotnet run` do it for you

---

### ✅ Framework vs Runtime

- **`net8.0`** — Cross-platform (Windows, Linux, Mac) — use this for new projects
- **`net8.0-windows`** — Windows-only (for WPF/WinForms)
- **`net48`** — Old .NET Framework (Windows-only, legacy) — avoid for new projects

---

### ✅ `System.Text.Json` vs `Newtonsoft.Json`

.NET 6+ ships with a **built-in JSON library** — no NuGet install needed:

```csharp
using System.Text.Json;

string json = JsonSerializer.Serialize(myObject);
MyClass obj = JsonSerializer.Deserialize<MyClass>(json);
```

Use `Newtonsoft.Json` only if you need advanced features (custom converters, LINQ to JSON, etc.).

---

### ✅ Top-Level Statements (C# 9+)

Modern C# doesn't need a `Main` method wrapper:

```csharp
// Old style (Java-like):
class Program {
    static void Main(string[] args) {
        Console.WriteLine("Hello World");
    }
}

// Modern C# (Program.cs):
Console.WriteLine("Hello World");
```

Both work — the compiler generates the `Main` method for you.
